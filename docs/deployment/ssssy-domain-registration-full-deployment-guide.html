Part 1 — Choose & Register the Domain

Your project already uses ssssy.org.sy throughout the codebase (nginx.conf, docker-compose.prod.yml, .env.example). Register that domain or adapt the steps below to any name you choose.

Step 1 Check Domain Availability

Go to one of these registrars and search for your domain:

RegistrarNotesApprox. .org Price/yr
NamecheapBest balance of price + UI$9–$13
PorkbunCheapest, free WHOIS privacy$8–$11
Google / SquarespaceClean UI, simple DNS$12–$15
GoDaddyWidely known, upsells heavily$12–$20

Syrian .sy domain: For ssssy.org.sy, registration goes through the Syrian NIC (tld.sy). You may need a local contact or use an international registrar that resells .sy domains. Alternatively, register ssssy.org via any global registrar — it is simpler and works the same way.

Step 2 Purchase the Domain

  1. Create an account on your chosen registrar.
  2. Add the domain to cart and complete payment.
  3. Fill in registrant contact details (name, email, address).
  4. Enable WHOIS Privacy Protection — usually free or $1/yr.
  5. Enable auto-renew so the domain does not expire.

Part 3 — Point DNS to Your Server

Step 4 Add DNS Records at Your Registrar

Go to your domain registrar's DNS management panel and add these records (replace 185.20.x.x with your real server IP):

TypeNameValueTTL
A@ (root)185.20.x.x300
Awww185.20.x.x300

DNS propagation takes 5 minutes to 48 hours. You can check with:

nslookup ssssy.org.sy
# or
dig ssssy.org.sy +short

Part 4 — Prepare the Server

Step 5 SSH into the Server & Install Prerequisites

# Connect via SSH
ssh root@185.20.x.x

# Update system
apt update && apt upgrade -y

# Install Docker
curl -fsSL https://get.docker.com | sh

# Install Docker Compose plugin
apt install -y docker-compose-plugin

# Verify
docker --version
docker compose version

Step 6 Create a Deployment User (Recommended)

# Create a non-root user for deployments
adduser ssssy
usermod -aG sudo ssssy
usermod -aG docker ssssy

# Switch to the new user
su - ssssy

Step 7 Open Firewall Ports

# Allow SSH, HTTP, and HTTPS
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
ufw status

Step 8 Clone the Repository onto the Server

Part 6 — Configure Environment Secrets

Step 9 Create the .env File

Copy the example and fill in every CHANGE_ME value:

cp backend/.env.example .env
nano .env

Key values to set (replace ssssy.org.sy with your actual domain):

# Database
DB_PASSWORD=a_strong_random_password_here

# JWT — generate with: openssl rand -hex 32
JWT_SECRET=paste_64_char_hex_here

# Redis
REDIS_PASSWORD=another_random_password

# MinIO storage
MINIO_ACCESS_KEY=minio_admin
MINIO_SECRET_KEY=another_random_password

# Your domain
APP_BASE_URL=https://ssssy.org.sy
APP_CORS_ALLOWED_ORIGINS=https://ssssy.org.sy,https://www.ssssy.org.sy

# SMTP (your email provider)
SMTP_HOST=smtp.yourprovider.com
SMTP_PORT=587
SMTP_USERNAME=noreply@ssssy.org.sy
SMTP_PASSWORD=your_smtp_password

# Frontend URLs (baked into Next.js at build time)
NEXT_PUBLIC_API_URL=https://ssssy.org.sy/api
NEXT_PUBLIC_APP_URL=https://ssssy.org.sy
NEXT_PUBLIC_STORAGE_URL=https://ssssy.org.sy/storage
Never commit the .env file to Git. It is already in .gitignore.

Part 7 — Obtain an SSL Certificate (HTTPS)

The nginx/nginx.conf already includes Let's Encrypt and certbot configuration. Certificates are free and auto-renew every 90 days.

Step 10 Update nginx.conf with Your Domain

Open nginx/nginx.conf and replace ssssy.org.sy with your actual domain in two places:

# Line 77 — server_name directive
server_name yourdomain.org www.yourdomain.org;

# Lines 80–81 — SSL certificate paths
ssl_certificate     /etc/letsencrypt/live/yourdomain.org/fullchain.pem;
ssl_certificate_key /etc/letsencrypt/live/yourdomain.org/privkey.pem;

Step 11 Temporarily Start nginx on HTTP Only

Before you have a certificate, comment out the SSL server block and run certbot's HTTP challenge:

# Start just nginx + certbot volumes (no HTTPS yet)
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d nginx certbot

Step 12 Issue the Certificate

docker compose -f docker-compose.prod.yml run --rm certbot certonly \
  --webroot -w /var/www/certbot \
  -d yourdomain.org \
  -d www.yourdomain.org \
  --email admin@yourdomain.org \
  --agree-tos \
  --no-eff-email

On success you will see: "Congratulations! Your certificate and chain have been saved..."

Part 8 — Deploy with Docker Compose

Step 13 Build & Start All Services

cd /opt/ssssy

# Build images and start all containers
docker compose \
  -f docker-compose.yml \
  -f docker-compose.prod.yml \
  --env-file .env \
  up -d --build

# Watch logs
docker compose -f docker-compose.prod.yml logs -f

This starts 6 services: postgres, redis, minio, backend, frontend, nginx, certbot.

Step 14 Run Database Migrations

Flyway migrations run automatically when the backend starts. Confirm in logs:

docker logs ssssy-backend 2>&1 | grep -i flyway
# Expected: Successfully applied N migration(s)

Step 15 Create the Admin User

# Connect to PostgreSQL inside the container
docker exec -it ssssy-postgres psql -U ssssy -d ssssy_website

-- Inside psql: insert your admin user
INSERT INTO users (
  id, username, email, password, role,
  first_name_en, last_name_en,
  is_active, is_email_verified, created_at, updated_at
) VALUES (
  gen_random_uuid(), 'admin', 'admin@ssssy.org.sy',
  -- bcrypt hash of your password (generate at bcrypt-generator.com)
  '$2a$12$REPLACE_WITH_REAL_BCRYPT_HASH',
  'ADMIN', 'Admin', 'User',
  true, true, now(), now()
);

\q

Part 10 — Auto-Deploy via GitHub Actions (CI/CD)

The project already has .github/workflows/ci.yml configured. On every push to main, it builds Docker images, pushes to GitHub Container Registry (GHCR), and SSH-deploys to your server.

Step 18 Add GitHub Repository Secrets

Go to your GitHub repo → Settings → Secrets and variables → Actions → New repository secret:

Secret NameValue
DEPLOY_HOSTYour server IP (185.20.x.x)
DEPLOY_USERssssy (the deploy user)
DEPLOY_SSH_KEYYour private SSH key (~/.ssh/id_rsa)
DEPLOY_PORT22
DEPLOY_PATH/opt/ssssy

Also add optional repository Variables (not secrets) if you want to override the default domain:

Variable NameValue
NEXT_PUBLIC_API_URLhttps://yourdomain.org/api
NEXT_PUBLIC_APP_URLhttps://yourdomain.org
NEXT_PUBLIC_STORAGE_URLhttps://yourdomain.org/storage

Step 19 Add the Server's SSH Key to Authorized Keys

# On your local machine: copy your public key to the server
ssh-copy-id ssssy@185.20.x.x

# Or manually on the server:
echo "YOUR_PUBLIC_KEY" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys

Step 20 Trigger a Deployment

# Push to main branch — CI/CD will run automatically
git push origin main

# Monitor progress at:
# https://github.com/YOUR_ORG/YOUR_REPO/actions

Part 11 — Ongoing Maintenance

Backup the Database

# Run daily backup (add to cron)
docker exec ssssy-postgres pg_dump -U ssssy ssssy_website \
  | gzip > /opt/ssssy/backups/backup_$(date +%Y%m%d_%H%M%S).sql.gz

Renew SSL Certificate

The certbot container renews automatically every 12 hours. To renew manually:

docker compose -f docker-compose.prod.yml run --rm certbot renew
docker compose -f docker-compose.prod.yml restart nginx

View Logs

# All services
docker compose -f docker-compose.prod.yml logs --tail=100 -f

# Specific service
docker logs ssssy-backend --tail=200 -f
docker logs ssssy-nginx --tail=200 -f

Update the Application

cd /opt/ssssy
git pull origin main

docker compose \
  -f docker-compose.yml \
  -f docker-compose.prod.yml \
  --env-file .env \
  up -d --build --remove-orphans

docker image prune -f
