3 — Phase 1: Register ssssyria.org

3.1 Understanding what a domain is

A domain name like ssssyria.org is a human-readable address that maps to a server's IP address. The Domain Name System (DNS) is the global "phone book" that resolves names to IPs. You rent the domain from a registrar (Porkbun) who is authorised by ICANN (the global authority) to sell it. You own the exclusive right to use it for the registration period — renew annually or lose it.

3.2 Do you need a professional email first?

No — a Gmail or any personal email is fine to register. You only need a professional info@ssssyria.org address after the domain is registered. Set that up in Phase 6.

  5. Complete payment via credit card or PayPal

4 — Phase 2: Railway Backend

4.1 What Railway hosts

  • Spring Boot 3 API on port 8080, built from backend/Dockerfile
  • PostgreSQL 16 — managed, private network, auto-migrated by Flyway on startup
  • Redis 7 — JWT token blacklist + rate-limiting token bucket
4

Create Railway project and deploy backend

  1. Go to railway.com → sign up with GitHub
  2. + New Project → Deploy from GitHub repo → select your repo
  3. Railway detects backend/Dockerfile automatically
  4. In service settings: Root Directory = backend
  5. Health Check Path = /actuator/health
5

Add PostgreSQL and Redis

  1. + New Service → Database → PostgreSQL
  2. + New Service → Database → Redis
  3. In backend service → Variables, add Railway references:
SPRING_DATASOURCE_URL=jdbc:postgresql://${{Postgres.PGHOST}}:${{Postgres.PGPORT}}/${{Postgres.PGDATABASE}}
SPRING_DATASOURCE_USERNAME=${{Postgres.PGUSER}}
SPRING_DATASOURCE_PASSWORD=${{Postgres.PGPASSWORD}}
REDIS_HOST=${{Redis.REDISHOST}}
REDIS_PORT=${{Redis.REDISPORT}}
REDIS_PASSWORD=${{Redis.REDISPASSWORD}}
The ${{ServiceName.VAR}} syntax is Railway's internal reference — it resolves automatically. No copy-pasting connection strings.
6

Set critical security variables

# Generate a secret: openssl rand -hex 32
JWT_SECRET=your_64_char_hex_here

SPRING_PROFILES_ACTIVE=prod
APP_BASE_URL=https://ssssyria.org
APP_CORS_ALLOWED_ORIGINS=https://ssssyria.org,https://www.ssssyria.org
APP_COOKIE_SECURE=true
JWT_SECRET is critical. Without it the app refuses to start. If it is leaked, anyone can impersonate any user. Generate with openssl rand -hex 32. Never commit it to Git.

5 — Phase 3: Netlify Frontend

7

Import repository on Netlify

  1. Go to netlify.com → sign up with GitHub
  2. Add new site → Import an existing project → GitHub
  3. Select your SSSS repo — Netlify reads netlify.toml automatically

Your netlify.toml is already configured correctly:

[build]
  base    = "frontend"
  command = "npm run build"
  publish = ".next"

[build.environment]
  NODE_VERSION = "20"
  NPM_FLAGS = "--legacy-peer-deps"

[[plugins]]
  package = "@netlify/plugin-nextjs"
8

Add API proxy rewrite to netlify.toml

This makes ssssyria.org/api/* proxy to Railway — the Railway URL is never exposed to users, CORS issues disappear:

[[redirects]]
  from   = "/api/*"
  to     = "https://YOUR-SERVICE.up.railway.app/api/:splat"
  status = 200
  force  = true

[[redirects]]
  from   = "/storage/*"
  to     = "https://pub-XXXX.r2.dev/ssss-media/:splat"
  status = 200
  force  = true
9

Set Netlify environment variables

Netlify → Site Configuration → Environment Variables:

NEXT_PUBLIC_API_URL=https://ssssyria.org/api
NEXT_PUBLIC_APP_URL=https://ssssyria.org
NEXT_PUBLIC_APP_NAME=SSSS
NEXT_PUBLIC_STORAGE_URL=https://ssssyria.org/storage
NEXT_PUBLIC_* variables are baked at build time. After changing them you must redeploy — push a commit or click "Trigger deploy" in Netlify.

6 — Phase 4: DNS & Domain Connection

10

Add domain in Netlify

  1. Netlify → your site → Site Configuration → Domain Management → Add a domain
  2. Enter ssssyria.org → Verify, then also add www.ssssyria.org
  3. Netlify shows exact DNS records to add — note them down
11

Add DNS records at Porkbun

  1. Porkbun → Domain Management → click DNS next to ssssyria.org
  2. Delete any existing A/CNAME records for @ and www
  3. Add:
TypeHostValueTTLPurpose
A@75.2.60.5 (Netlify IP from your dashboard)300ssssyria.org → Netlify
CNAMEwwwyour-site.netlify.app300www.ssssyria.org → Netlify

TTL explained: 300 = 5 minutes caching (fast propagation during setup). Raise to 3600 (1 hour) once stable.

DNS propagation takes 5 minutes to 48 hours. Check at dnschecker.org — green checkmarks worldwide = complete.
12

HTTPS certificate — fully automatic

Once Netlify sees your DNS pointing to it, it automatically issues a free Let's Encrypt SSL certificate. No action needed. Status changes to "HTTPS certificate: Active" in the Netlify domain panel within 5–15 minutes. Renewed automatically every 90 days.

Phase 6 — Brevo SMTP (transactional email)

13

Set up Brevo

  1. Create account at brevo.com
  2. Go to SMTP & API → SMTP — note Host, Port, Login, Password (SMTP key)
  3. Go to Senders, Domains → Add a domain → enter ssssyria.org
  4. Add the DNS records Brevo gives you in Porkbun:
TypeHostValuePurpose
TXT@v=spf1 include:spf.brevo.com ~allSPF — authorise Brevo to send on your behalf
TXTmail._domainkey(DKIM key from Brevo)DKIM — sign emails cryptographically
Domain verification dramatically improves deliverability. Without it, password reset emails often land in spam.

9 — Security Hardening Checklist

Secrets — verify before going live

  • JWT_SECRET set in Railway (generated, not default)
  • SPRING_DATASOURCE_PASSWORD is a strong random password
  • REDIS_PASSWORD is set
  • R2 Access Key and Secret Key are set
  • No secrets in Git (.env files are in .gitignore)

Authentication

  • APP_COOKIE_SECURE=true — JWT in httpOnly Secure cookie
  • SPRING_PROFILES_ACTIVE=prod
  • APP_SWAGGER_ENABLED=false
  • Test: login → JWT in httpOnly cookie, NOT in localStorage
  • Test: logout → subsequent API calls return 401
  • Test: 5 wrong passwords → account locked 15 min (6th attempt returns 423)
  • Test: 6th login attempt in 15 min → 429 rate limit

Domain & HTTPS

  • https://ssssyria.org loads with green padlock
  • http://ssssyria.org redirects to https automatically
  • Response header: Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
  • Response header: X-Frame-Options: DENY
  • Response header: X-Content-Type-Options: nosniff
  • Registrar Lock ON at Porkbun
  • Auto-Renew ON at Porkbun
  • 2FA ON on Porkbun account

Email

  • Brevo SMTP configured and tested
  • SPF and DKIM DNS records added and verified in Brevo
  • Password reset email arrives in inbox (not spam)
  • Member registration automatically assigns @ssssyria.org address

  │
  ├── backend-build   → mvn compile + test + package

13 — Renewal & Ongoing Maintenance

Annual

  • Domain renewal: Auto-renew is ON — Porkbun charges your card automatically. Verify your payment method is up to date each year.
  • SSL certificate: Auto-renewed by Netlify every 90 days — no action needed.

Monthly

  • Railway usage: Check Railway → Usage tab. If usage approaches $5 credit, consider upgrading or reducing resource limits.
  • Netlify build minutes: Netlify → Team → Billing. Free: 300 min/mo (~60 deploys).
  • Cloudflare R2: Check storage usage in R2 dashboard. Free: 10 GB.

pg_dump -U $PGUSER $PGDATABASE | gzip > backup_$(date +%Y%m%d).sql.gz
