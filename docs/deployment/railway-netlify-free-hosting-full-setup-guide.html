1 — Short Answer

Yes, you can absolutely continue with Railway + Netlify. Your codebase already has Railway and Netlify configuration in place — netlify.toml, the @netlify/plugin-nextjs, and ssssy-websit-production.up.railway.app is already whitelisted in next.config.mjs. No fundamental rewrites needed.

The only things you need to do are: set the right environment variables on each platform, point your custom domain, and make CORS work across the two origins.

2 — What Each Platform Hosts

Railway — Backend Services

  • Spring Boot API (:8080)
  • PostgreSQL database
  • Redis cache
  • MinIO object storage (or swap for Railway Volumes)

Netlify — Frontend

  • Next.js (via @netlify/plugin-nextjs)
  • SSR / ISR / API routes run as Netlify Functions
  • Static assets on Netlify CDN

4 — Architecture Overview

User browser
    │
    ├─► Netlify CDN  (www.ssssy.org.sy)
    │       └─► Next.js SSR / API routes → Netlify Functions
    │
    └─► Railway      (api.ssssy.org.sy  OR  ssssy-websit-production.up.railway.app)
            ├─► Spring Boot  :8080
            ├─► PostgreSQL
            ├─► Redis
            └─► MinIO (object storage)

Netlify calls Railway's backend for all /api/* requests. Static images/media are served from Railway MinIO or proxied through Netlify rewrites.

Part A — Configure the Backend on Railway

Step 1 Create a Railway Project

  1. Go to railway.com → New Project.
  2. Choose Deploy from GitHub repo → select your repository.
  3. Railway will detect the backend/Dockerfile automatically.
  4. Set the Root Directory to backend in service settings.

Step 2 Add PostgreSQL & Redis

  1. In your Railway project → + New Service → Database → PostgreSQL.
  2. In your Railway project → + New Service → Database → Redis.
  3. Railway automatically injects DATABASE_URL and REDIS_URL — but your Spring Boot app reads them differently, so map them below.

Step 3 Set Backend Environment Variables on Railway

In your backend service → Variables tab, add:

SPRING_PROFILES_ACTIVE=prod

# PostgreSQL — use the Railway internal URL
SPRING_DATASOURCE_URL=jdbc:postgresql://${{Postgres.PGHOST}}:${{Postgres.PGPORT}}/${{Postgres.PGDATABASE}}
SPRING_DATASOURCE_USERNAME=${{Postgres.PGUSER}}
SPRING_DATASOURCE_PASSWORD=${{Postgres.PGPASSWORD}}

# Redis — use the Railway internal URL
REDIS_HOST=${{Redis.REDISHOST}}
REDIS_PORT=${{Redis.REDISPORT}}
REDIS_PASSWORD=${{Redis.REDISPASSWORD}}

# JWT — generate: openssl rand -hex 32
JWT_SECRET=paste_your_64_char_hex_here

# Your domain (Netlify frontend URL)
APP_BASE_URL=https://www.ssssy.org.sy
APP_CORS_ALLOWED_ORIGINS=https://www.ssssy.org.sy,https://ssssy.org.sy,https://ssssy-websit.netlify.app

# Cookies must be Secure over HTTPS
APP_COOKIE_SECURE=true

# SMTP (your email provider)
SMTP_HOST=smtp.yourprovider.com
SMTP_PORT=587
SMTP_USERNAME=noreply@ssssy.org.sy
SMTP_PASSWORD=your_smtp_password

# MinIO — you can use Railway Volumes or an external S3 bucket
STORAGE_TYPE=minio
MINIO_ACCESS_KEY=your_minio_key
MINIO_SECRET_KEY=your_minio_secret
MINIO_BUCKET=ssssy-media

# Logging
LOG_LEVEL=INFO
Railway variables using ${{ServiceName.VAR}} syntax are automatically resolved — no copy-pasting of connection strings needed.

Step 4 Configure the Railway Port

Railway auto-detects the EXPOSE 8080 in your backend/Dockerfile. In service settings, confirm:

  • Port: 8080
  • Health Check Path: /actuator/health

Railway will give your backend a public URL like https://ssssy-websit-production.up.railway.app.

Part B — Configure the Frontend on Netlify

Step 5 Check netlify.toml (Already Correct)

Your netlify.toml is already set up correctly:

[build]
  base    = "frontend"
  command = "npm run build"
  publish = ".next"

[build.environment]
  NODE_VERSION = "20"
  NPM_FLAGS = "--legacy-peer-deps"

[[plugins]]
  package = "@netlify/plugin-nextjs"

No changes needed here.

Step 6 Set Frontend Environment Variables on Netlify

Go to Netlify → your site → Site Configuration → Environment Variables → Add:

# Replace with your actual Railway backend URL
NEXT_PUBLIC_API_URL=https://ssssy-websit-production.up.railway.app/api

# Your Netlify site URL (or custom domain after you connect it)
NEXT_PUBLIC_APP_URL=https://www.ssssy.org.sy
NEXT_PUBLIC_APP_NAME=SSSSY

# MinIO storage URL (Railway backend proxies it, or use direct MinIO URL)
NEXT_PUBLIC_STORAGE_URL=https://ssssy-websit-production.up.railway.app/storage
Important: NEXT_PUBLIC_* variables are baked into the JavaScript bundle at build time. After changing them you must trigger a new Netlify deploy (push a commit or click "Trigger deploy").

Step 7 Add a Netlify Rewrite for API Calls (Recommended)

Instead of calling Railway directly from the browser (which exposes your Railway URL and causes CORS complexity), add a Netlify rewrite so /api/* proxies to Railway:

Add this to your netlify.toml:

[[redirects]]
  from   = "/api/*"
  to     = "https://ssssy-websit-production.up.railway.app/api/:splat"
  status = 200
  force  = true

[[redirects]]
  from   = "/storage/*"
  to     = "https://ssssy-websit-production.up.railway.app/storage/:splat"
  status = 200
  force  = true

Then change NEXT_PUBLIC_API_URL to your own Netlify domain:

NEXT_PUBLIC_API_URL=https://www.ssssy.org.sy/api

Now the frontend calls /api/* on Netlify, which proxies to Railway — no CORS issues at all.

Part C — Connect Your Custom Domain

Step 8 Add Domain to Netlify (Frontend)

  1. Netlify site → Domain Management → Add custom domain.
  2. Enter www.ssssy.org.sy and ssssy.org.sy.
  3. Netlify gives you DNS records to add at your registrar:
TypeNameValue
CNAMEwwwyour-site.netlify.app
A@ (root)75.2.60.5 (Netlify's IP)

Netlify provisions HTTPS (Let's Encrypt) automatically — no manual cert needed.

Step 9 Add Custom Domain to Railway (Backend — Optional)

If you want a clean API URL like api.ssssy.org.sy:

  1. Railway service → Settings → Domains → Custom Domain.
  2. Enter api.ssssy.org.sy.
  3. Add the CNAME record at your registrar: api → your-service.up.railway.app
  4. Update NEXT_PUBLIC_API_URL on Netlify to https://api.ssssy.org.sy/api.
Custom domains on Railway require the Starter plan ($5/mo). On the free hobby plan you use the .up.railway.app URL directly.

Part D — Fix CORS & Cookies for Cross-Origin Setup

Step 10 Update CORS on the Backend

Your Spring Boot app reads APP_CORS_ALLOWED_ORIGINS. Make sure it includes all frontend origins on Railway:

# In Railway backend environment variables:
APP_CORS_ALLOWED_ORIGINS=https://www.ssssy.org.sy,https://ssssy.org.sy,https://your-site.netlify.app

Step 11 Cookie SameSite for Cross-Origin

Since Netlify (frontend) and Railway (backend) are on different domains, JWT cookies set by the backend need SameSite=None; Secure. Check your backend cookie configuration in application.yml and make sure:

# In Railway backend environment variables:
APP_COOKIE_SECURE=true

And verify your SecurityConfig.java sets SameSite=None when running cross-origin. If using the Netlify proxy rewrite from Step 7, this problem disappears — same origin, no cookie issues.

9 — Things That Won't Work on Free Tiers

FeatureProblemSolution
MinIO file storage Railway free tier has no persistent disk — MinIO data is lost on redeploy Use Railway Volumes ($0.25/GB/mo) or swap to Cloudflare R2 (free 10GB) / Backblaze B2 (free 10GB)
Cold starts Spring Boot sleeps after inactivity on free tier — slow first request Upgrade to Railway Starter ($5/mo) — no sleep
WebSockets (real-time) Netlify Functions do not support persistent WebSocket connections WebSocket connects directly to Railway backend URL (bypass Netlify proxy for /ws path)
Email (IMAP sync) Requires persistent background process — fine on Railway, just set SMTP/IMAP env vars Configure SMTP_* and IMAP_* variables in Railway
Netlify build minutes 300 min/mo free — each Next.js build takes ~3–5 min ~60 deploys/month free; plenty for a small team

10 — When to Upgrade / Move to a VPS

SignalAction
Backend cold starts annoy real usersUpgrade to Railway Starter ($5/mo)
Monthly Railway bill exceeds $15–20Move backend to Hetzner VPS (~$4/mo) using the Docker guide
You need MinIO with large media filesAdd Railway Volume or use Cloudflare R2 (free 10 GB)
You need WebSocket on same domainMove to VPS with Nginx reverse proxy (already configured in nginx/nginx.conf)
Netlify build minutes run outMove frontend to Vercel (free, 6000 build minutes/mo) or self-host
Bottom line: Railway + Netlify is a perfectly valid production setup for a low-to-medium traffic site. Your codebase is already wired for it. Start free, upgrade only when you need to.
