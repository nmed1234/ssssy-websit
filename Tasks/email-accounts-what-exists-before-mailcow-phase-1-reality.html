Email Accounts — What Exists Before Mailcow

Honest answer based on reading the actual source code — not assumptions

The One-Line Answer

Before Mailcow, the email addresses like ahmad@ssssyria.org exist only as records in your PostgreSQL database. They are NOT real, working email addresses. No email can be sent TO them from outside, and no email sent FROM them reaches a real inbox.

Think of it like this: you have a phone book listing with a name and phone number, but the phone line is not connected yet. The listing is real, the number is assigned — but calls don't go through until you connect the line (= Mailcow).

Exactly What Gets Created on Member Registration

When a member registers (after your fix in AuthService.register()), this runs in EmailAccountService.provisionAccount():

Member registers │ ▼ EmailAccountService.provisionAccount() │ ├── Creates row in email_accounts table: │ emailAddress = "ahmad.hassan@ssssyria.org" │ username = "ahmad.hassan" │ passwordHash = bcrypt(random 12-char temp password) │ quotaBytes = 1,073,741,824 (1 GB) │ isActive = true │ isVerified = false │ └── Creates 6 rows in email_folders table: Inbox (INBOX) Sent (SENT) Drafts (DRAFTS) Trash (TRASH) Spam (SPAM) Archive (ARCHIVE)
That's it. Only database rows. No connection to any mail server. No IMAP mailbox. No SMTP account. The address ahmad.hassan@ssssyria.org is stored in PostgreSQL but does not exist anywhere on the internet.

How Internal Messaging Works Without Mailcow

This is the clever part of your code. When a member sends to another member on the same site, the code detects it is an internal address and completely bypasses SMTP:

// EmailSendService.java line 131-134
for (EmailRecipient r : recipients) {
    if (Boolean.TRUE.equals(r.getIsInternal())) {
        deliverInternal(r.getAddress(), message, threadId);
        // → writes directly to recipient's inbox in the DB
        // → no email server involved at all
    }
}

// isInternal is true when address ends with @ssssyria.org
// EmailSendService.java line 383:
boolean isInternal = address.toLowerCase().endsWith("@ssssyria.org");
This means your members CAN already message each other through the website — like an internal messaging system — without any email server. Ahmad can send a message to Fatima, it appears in Fatima's inbox on the website, she can reply, forward, save drafts. This all works in Phase 1.

How Members Access Their Inbox — Before Mailcow

Members access their inbox only through the SSSS website. There is no external access (no Outlook, no Thunderbird, no phone app) until Mailcow is added.

Access method: Website inbox at ssssyria.org

Your frontend has API endpoints for the inbox. The member logs in to the website and accesses their email through the built-in web interface at a URL like:

https://ssssyria.org/dashboard/email
https://ssssyria.org/dashboard/email/inbox
https://ssssyria.org/dashboard/email/compose
Note: The frontend UI pages for the inbox need to be built — the backend API is complete, but the frontend inbox pages (the visual interface members use to read and write emails) were not found in the codebase. This means you need to build the inbox UI in Next.js. The APIs to call are all ready.

For a scientific society, this is very useful for internal committee communication. The full "real email" experience comes in Phase 2 with Mailcow.
