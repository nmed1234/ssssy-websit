Events Admin Panel — Full Enhancement Plan

5-phase roadmap to build a production-grade Event Management system with full CRUD, registrations management, configurable reminder notifications, email blasts, check-in, analytics, and public page controls — all from the admin panel.

⚠ Current Gaps Found

  • Admin list page exists at /admin/events but the "Edit" button opens a small modal — no dedicated detail/edit page
  • No /admin/events/[id] route — clicking an event links there but the page does not exist
  • Registrations are viewable via API (GET /api/admin/events/{id}/registrations) but no UI page exposes them
  • No registration status change (confirm / cancel / check-in) from admin
  • No notification system for event registrants (reminder emails, post-event surveys)
  • No configurable reminder timing (e.g. "send 24h before event") in admin panel
  • No bulk notification/email to all registrants from admin
  • No event statistics / analytics page in admin
  • Edit modal is missing: slug, endDate, featuredImage, latitude/longitude, isOnline/onlineUrl fields
  • No "Duplicate event" or "Archive" quick action
  • No public page controls (featured toggle, order, hero image) in admin

Phase 3 Configurable Notification & Reminder System ~2 days

The core new feature. Admin configures reminder schedules per event; a background scheduler fires email + in-app notifications to all confirmed registrants at the right time.

Architecture

Admin Panel └─ configure reminder rules for event [24h before] [1h before] [post-event: 2h after] Scheduler (60s cron) — EventReminderService └─ SELECT rules WHERE fire_at <= NOW() AND fired = false └─ fetch all CONFIRMED registrations for event └─ for each registrant: ├─ NotificationService.createAndPush(user, "event_reminder", …) └─ EmailSendService.sendTransactional(email, template) └─ mark rule as fired
Database

Migration V66 — event_reminder_rules table

  • id UUID PK
  • event_id FK → events
  • rule_type: BEFORE_EVENT | AFTER_EVENT | CUSTOM_DATE
  • offset_hours INTEGER (e.g. 24 = "24h before")
  • fire_at TIMESTAMP (computed on save)
  • subject_template TEXT
  • body_template TEXT (with {{name}}, {{event}}, {{date}}, {{link}} placeholders)
  • send_email BOOLEAN DEFAULT true
  • send_in_app BOOLEAN DEFAULT true
  • is_fired BOOLEAN DEFAULT false
  • fired_at TIMESTAMP
  • recipients_count INTEGER (filled after fire)
  • created_at / updated_at
Backend

EventReminderService (new)

  • CRUD for reminder rules
  • computeFireAt(): event.eventDate minus offset_hours
  • @Scheduled(fixedDelay=60000) processDueReminders()
  • For each due rule: load confirmed registrants, fire notifications
  • Template substitution: {{name}}, {{eventTitle}}, {{eventDate}}, {{location}}, {{link}}
  • Mark rule as fired + record count
  • Handle AFTER_EVENT rules for post-event follow-ups

Notification Flow — Full Picture

1. User registers → EventService.registerForEvent() └─ [Immediate] send confirmation email (HTML + iCal attachment) └─ [Immediate] create in-app Notification (type: "event_registration") 2. Admin publishes event → EventController.updateEvent() / status change └─ [Auto] EventReminderService.createDefaultReminders(eventId) reads system_config for default offsets (e.g. [24h, 1h]) creates event_reminder_rules rows with computed fire_at 3. Scheduler (every 60s) — EventReminderService.processDueReminders() └─ SELECT * FROM event_reminder_rules WHERE fire_at <= NOW() AND is_fired = false for each rule: load CONFIRMED registrations for rule.event_id for each registration: if send_email: JavaMailSender.send(template substituted) if send_in_app: NotificationService.createAndPush(user, …) rule.is_fired = true rule.fired_at = NOW() rule.recipients_count = N 4. Admin "Send Now" → POST /admin/events/{id}/reminders/{ruleId}/fire └─ same logic as scheduler step, immediate execution 5. Admin "Message Registrants" → POST /admin/events/{id}/notify └─ custom ad-hoc message to selected registrant group 6. Admin cancels event └─ sets status = CANCELLED, isPublished = false └─ optionally fires cancellation notification to all registrants
